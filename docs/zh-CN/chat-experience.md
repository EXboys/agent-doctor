# 聊天体验：报错怎么排查

这是聊天里「用户看见一段不该看见的原文」时的排查标准。先按下面四步看截图，再改。不要为某一句英文报错、某一个目录或某一个应用加分支。

行业里同一类界面（GitHub Actions、Xcode、浏览器开发者工具、对话产品里的工具卡片）都是这么分的：操作结果写在那条操作上，原始日志收在里面，默认不展开。

## 四步

1. **这件事已经画在哪了？**  
   工具行、确认卡片、失败气泡，先找已经代表这一步的那一块。找到了，原文就进那一块，不要在下面再铺一行。

2. **露在外面的是不是人话？**  
   外面只留一句用户能对上的话，或者工具行上已有的状态（例如「没成功」）。时间戳、模块名、英文报错、脚本，都是里面的原文。

3. **原文默认折叠。**  
   用户点开那一条才看见原文。原文可以完整保留。

4. **控制字符不是文字。**  
   终端颜色码（包括前面的 ESC 被吃掉后剩下的 `[31m`、`[0m`）先剥掉，再决定显示什么。颜色码不能出现在句子里。

## 什么算运行日志

看形状，不看报错原文：

- 带颜色码，或
- 有时间戳，并且有 ERROR / WARN / INFO 这种级别

这种行不是一条新的聊天消息。

## 放哪

- 屏幕上已经有对应的工具行：把剥掉颜色码的原文追加进那一行，那一行保持折叠。
- 没有工具行：外面一句「这一步的命令没跑成」，里面是原文，默认折叠。

## 一轮结束

步骤收成一条，默认折叠。点开才看见每一步。

没有正文时，不要把「某个运行时结束了、没有输出」这种状态句当成结论。外面写：这一轮做完了，但没有写出结论。

## 不要做的

- 不要按 `write_stdin`、`exec_command`、某个软件名、某个文件夹再写一条文案。
- 不要让同一条失败既在工具行上标红，又在下面再贴一整段日志。
