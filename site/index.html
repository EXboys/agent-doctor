Scan, explain, then repair.

The same loop every time an agent stops connecting, asks for a key, or starts mixing one project with another.

  1. 01

    Scan

    Lists the agents on this computer and scores the environment. You see what is installed and what is waiting.

  2. 02

    Diagnose

    Says the problem in words you already use: this project, this tool, cannot connect, needs a key.

  3. 03

    Repair

    You confirm first. Agent Doctor takes a backup, applies a typed fix, then checks again. You can roll back to that backup.

Your endpoint, written into each agent

Bring your own address, key, and model. Agent Doctor writes that connection into the agents on this computer and checks that it answers.

Projects stay separate

Switch the active project so one project’s memory and tools do not leak into the next one.

Ask it to look again

After a repair, ask in a sentence why something still fails. The check runs through the agent that is already installed.

A repair you can undo.

Agent Doctor writes only through typed actions. It takes a backup first, and it does not invent a shell command.

  • Preview, then apply The first pass only reads. Nothing is written until you confirm.
  • Backup, then a typed fix The backup sits on this computer. Roll back to it if the repair is wrong.
  • Keys stay here Secrets are removed before an explanation is written. A missing key becomes a placeholder and a short guide. You paste the secret yourself.
  • Still early The app is in active use and still before 1.0. The scan, diagnose, and repair loop is the part you can rely on today.
